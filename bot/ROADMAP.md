# AvitoBroBot — бот для ответов в чатах Авито

Источник: созвон в Телемосте 09.11.2026. Участники: **Данила** (идея, интеграции, свой проект с QR-стикерами), **Максим** (продавец, сейчас сам отвечает во всех чатах), **Гришка** (разработчик и аналитик, разрабатывает бота).

Магазин продаёт джинсы на Авито. Сейчас есть 2 вида товара, скоро добавятся куртки и другие.

---

## 1. Итоги встречи: что решили

### Цель MVP
Бот **понимает контекст** сообщения покупателя: определяет, к какой категории относится вопрос, и отвечает правильно, опираясь на данные магазина (размерные сетки, фото, условия). Это главная задача. Всё остальное (косметика, интеграции) идёт после.

### Как бот отвечает
- Классифицирует входящее сообщение по категориям вопросов (таблица ниже).
- Из текста вытаскивает нужные данные, например **рост и вес**, и подбирает размер по сетке конкретной модели джинсов.
- Отвечает **заготовленными, но «живыми» и вариативными** формулировками, а не пишет каждый ответ с нуля. У шаблонов несколько вариантов, которые выпадают с заданной вероятностью, чтобы ответы не повторялись.
- Если бот не справляется (непонятный вопрос, конфликт, краевой случай), он **отправляет Максиму уведомление в Telegram**: нужно подключиться к чату.
- Главный риск, о котором говорил Максим: покупатели на Авито любят живую переписку, и если будет заметно, что отвечает робот, не купят. Поэтому формулировки должны звучать по-человечески.

Причины жалоб после получения:

| Причина | Чатов |
|---|---|
| Малы или тесные: талия, бёдра, ляжки, пах | 19 |
| «Не подошли», без подробностей | 6 |

Вывод: подбор размера и размерная сетка встречаются в большинстве чатов, поэтому точность подбора размера важнее всего остального.

### Проактивные сообщения (бот пишет сам)
1. **Покупатель оформил заказ и ничего не написал.** Через N минут: «Здравствуйте! Напишите свой рост и вес, помогу подобрать размер».
2. **Цепочка касаний по заказу:**
   - заказ отправлен;
   - заказ пришёл в пункт выдачи;
   - напоминание забрать;
   - покупатель забрал → **два разных сообщения**: для случая «принял» и для случая «отказался»;
   - после принятия: попросить оставить отзыв.
3. **Сделка не закрыта** в течение N часов: «Привет! Выбрали джинсы? Что-то смутило?»
4. **Автоматический отзыв покупателю** (на случай, если это возможно сделать). ⚠️ Публичное API позволяет только читать отзывы и отвечать на них, оставить отзыв покупателю через API нельзя (см. [docs/avito-api.md](docs/avito-api.md)).

### После MVP (отложили)
- **Задержка ответа 10–30 секунд** и имитация набора текста, чтобы не было видно, что отвечает бот. Задержку сделать просто; индикатора «печатает» в API Мессенджера нет.
- **Быстрые вопросы / быстрые ответы** (кнопки-подсказки внизу чата). Сейчас они настроены плохо; если задать правильные, покупатель сам выберет нужный вопрос. Задача не первостепенная, но направление правильное. Скорее всего настраивается в кабинете продавца на Авито, а не через API.
- **Интеграция с печатью QR-стикеров** (проект Данилы): бот определил размер → размер попадает в стикер для термопринтера. Сейчас проект Данилы стоит именно потому, что неизвестен размер.
- Интеграция с сайтом.
- Продажа бота как **подписки** другим продавцам на Авито (у Максима есть сообщество продавцов, которым нужен такой сервис).

### Тестирование
1. **Этап 1: демо.** Гришка в чате с собой показывает, что бот правильно отвечает на вопросы из таблицы.
2. **Этап 2: неделя в «теневом режиме».** Максим отвечает как обычно, а бот на каждое сообщение генерирует свой ответ, не отправляя его. По итогам недели сравниваем ответы бота и Максима. Цель: около **90% совпадения** по смыслу. Обучаем на старых чатах, проверяем на чатах этой недели.
3. **Этап 3: калибровка** (ещё неделя, Гришка вместе с командой): разбираем ошибки и краевые случаи (сокращения, нестандартные формулировки).
4. События заказа (отправлен / принят / отказ) Максим и Данила сами заказывать не будут, поэтому их проверяют на реальных покупателях.

### Деньги и формат работы
- За MVP Гришке **15 000 ₽**. В сумму входит то, что перечислено в критерии готовности ниже, без интеграций и косметических доработок.
- Если пойдут продажи подписки, Гришка получает долю. Размер и формат (процент от подписки или иначе) **обсудят позже**.
- Код хранится в **приватном GitHub-репозитории**, Гришку добавляют в команду. Данила тоже работает в репозитории (через Claude Code), чтобы потом дописывать интеграции.

### Критерий готовности MVP (к следующей встрече)
Гришка возвращается, когда бот:
- [ ] отвечает на всё из таблицы категорий, **кроме отзывов**;
- [ ] видит статус заказа: отправлен / пришёл / отказ / принят;
- [ ] умеет показывать рядом ответ Максима и свой ответ для сравнения.

## 2. Роудмап

### Этап 0. Подготовка (Данила и Максим, до старта разработки)
- [ ] **Данила:** создать приватный репозиторий на GitHub, положить туда этот файл, подключить Claude Code.
- [ ] **Данила:** узнать у Гришки ник на GitHub и добавить его в репозиторий.
- [ ] **Максим:** проверить, что у аккаунта подписка **«Максимальный»**. Без неё Messenger API в категории «Товары» недоступен.
- [ ] **Максим:** в кабинете **основного аккаунта компании** получить `client_id` и `client_secret` и передать Гришке безопасным способом (не в общий чат и не в репозиторий). ⚠️ Доступ сотрудника, который Гришке уже выдали, для API не подходит: с ключом сотрудника нельзя читать и отправлять сообщения по объявлениям компании.
- [ ] **Максим:** уточнить, подключена ли **Авито Доставка для бизнеса**. API «Управление заказами» (статусы заказов) работает только с ней. Если её нет, статусы придётся брать другим способом (см. риски).
- [ ] **Максим:** прислать **размерные сетки** по каждой модели: картинкой (чтобы отправлять покупателям) и таблицей (чтобы бот считал).
- [ ] **Максим:** описать, **как он сейчас подбирает размер** по росту и весу (правила, исключения: «если бёдра широкие — брать на размер больше» и т. п.).
- [ ] **Максим:** прислать паки **фото на человеке** по каждой модели (в том числе на девушке).
- [ ] **Максим:** прислать тексты по доставке, оплате, примерке и возврату, материалу, наличию: то, что он обычно отвечает.
- [ ] **Максим:** определить значения N: через сколько минут писать покупателю, который заказал молча, и через сколько часов дожимать незакрытую сделку.
- [ ] Создать Telegram-бота для уведомлений Максиму («нужно подключиться к чату») и получить его токен.
- [ ] Решить, **где бот будет работать** (см. открытые вопросы): вебхукам Авито нужен публичный HTTPS-адрес, который работает круглосуточно.

### Этап 1. Каркас и доступ к API
- [ ] Получение и обновление токена (`POST https://api.avito.ru/token`, client_credentials).
- [ ] Узнать свой `user_id` (API «Информация о пользователе»).
- [ ] Выгрузить историю чатов и сообщений (`/messenger/v2/.../chats`, `/messenger/v3/.../messages`) для обучения и проверки.
- [ ] Поднять эндпоинт для вебхука и подписаться (`POST /messenger/v3/webhook`); эндпоинт должен отвечать 200 в пределах 2 секунд, поэтому обработку выносим в очередь.
- [ ] Хранилище: чаты, сообщения, состояние диалога, заказы, отправленные проактивные сообщения.

### Этап 2. Понимание сообщений (ядро MVP)
- [ ] Классификатор по 13 категориям (на основе разметки Гришки).
- [ ] Извлечение роста, веса и других параметров (талия, «люблю посвободнее»), в том числе из коротких и кривых формулировок.
- [ ] Определение, о какой модели речь: по объявлению, к которому привязан чат (`context` в чате → `item_id`).
- [ ] Подбор размера по сетке модели и правилам Максима.
- [ ] Банк шаблонов ответов по каждой категории с вариантами и вероятностями.
- [ ] Отправка размерной сетки и фото картинками (`uploadImages` → `messages/image`).
- [ ] Эскалация: низкая уверенность или жалоба → уведомление в Telegram, бот в этом чате замолкает.
- [ ] Не отвечать на системные сообщения Авито (`type: system`).

### Этап 3. Теневой режим и сравнение с Максимом
- [ ] Режим «не отправлять, а записать»: на каждое сообщение покупателя сохраняем ответ бота.
- [ ] Отчёт «ответ Максима ↔ ответ бота» по каждому чату.
- [ ] Неделя сбора, подсчёт совпадения, цель около 90%.
- [ ] Неделя калибровки по ошибкам.

### Этап 4. Заказы и проактивные сообщения
- [ ] Получение статусов заказов (`GET /order-management/1/orders`, статусы `on_confirmation`, `ready_to_ship`, `in_transit`, `delivered`, `canceled`, `on_return`, `in_dispute`, `closed`). Опрашивать по расписанию.
- [ ] Связь заказа с чатом покупателя.
- [ ] Цепочка сообщений: отправлен → в пункте выдачи → напоминание → принял / отказ → просьба об отзыве.
- [ ] «Заказал и молчит» через N минут.
- [ ] «Сделка не закрыта» через N часов.
- [ ] Защита от повторной отправки одного и того же сообщения.

**→ Здесь MVP готов: встреча, приёмка, оплата 15 000 ₽.**

### Этап 5. После MVP
- [ ] Задержка ответа 10–30 с.
- [ ] Быстрые вопросы и ответы в кабинете Авито.
- [ ] Ответы на отзывы (`/ratings/v1/answers`).
- [ ] Расшифровка голосовых сообщений покупателей (API отдаёт ссылку на файл).
- [ ] Новые товары (куртки): новая сетка и шаблоны без переписывания кода.
- [ ] Интеграция с печатью QR-стикеров (проект Данилы); у API заказов есть методы для этикеток `/order-management/1/orders/labels`.
- [ ] Мультиаккаунтность для продажи подписки другим продавцам (OAuth authorization_code).

## 3. Открытые вопросы
1. **Где запускать бота.** Нужен сервер, работающий круглосуточно, с публичным HTTPS-адресом для вебхука. Варианты: арендованный VPS или своя машина.
2. **Шаблоны или языковая модель.** Договорились о шаблонах с вариативностью. Гришка упоминал небольшие локальные модели (по его словам, Qwen 2B/4B, нужна видеокарта примерно от 4 ГБ видеопамяти) как вариант для понимания текста. Нужно решить, нужна ли модель вообще и где она будет работать.
3. **Статусы заказов без «Доставки для бизнеса».** Если её нет, проверить, приходят ли события заказа системными сообщениями в чат, и брать статусы оттуда.
4. **Автоотзыв покупателю.** В публичном API такого метода нет; если без него никак, остаётся делать вручную.
5. **Доля Гришки в подписке**: обсудить после MVP.
